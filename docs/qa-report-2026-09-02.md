## Issues and fixes

### ISSUE-001: Browser confirmation could be auto-resolved

- **Severity:** Critical
- **Category:** Functional
- **Fix status:** Verified
- **Commit:** `4e1f7b2`
- **Files:** `client/src/lib/agent-confirmation.ts`, `client/src/components/agent-confirmation-dialog.tsx`, `client/src/hooks/use-webmcp.ts`, `client/src/App.tsx`, `tests/agent-confirmation.test.ts`

**Before:** A direct native `start_fast` WebMCP call reached `window.confirm()`, which the host could resolve without a visible human decision. The timer changed even though the product promised explicit approval.

**Fix:** Saved agent actions now wait on an app-owned modal controller. The request stays pending until the person selects **Cancel** or the named approval button. Overlapping and aborted requests fail closed.

**After:** Manual live verification in the OpenAI in-app browser showed that native WebMCP cancel left the tracker idle with 11 records. Native approve created one active 18-hour fast, changed the visible count to 12, produced agent activity, and returned the active record through `get_current_fast`. Reset restored the 11-record idle baseline.

Evidence: [approval-gate frame](screenshots/approval-gate.png)

### ISSUE-002: Reset left prior demo activity visible

- **Severity:** Medium
- **Category:** UX
- **Fix status:** Verified
- **Commit:** `37c344b`
- **Files:** `worker/actions.ts`, `tests/demo-activity-reset.regression-1.test.ts`

**Before:** The data reset restored synthetic fasting history but the first panel could still say that an agent had just started a fast. That made a fresh judge session look dirty.

**Rejected fix:** Deleting audit events would have violated the append-only audit design, so that attempt was reverted.

**Fix:** The activity panel now queries successful tracker activity after the latest successful `demo.reset` event. Audit records remain intact.

**After:** Reset returns 11 completed records, no active fast, the starting workspace, and no pre-reset activity in the visible panel.

### ISSUE-003: Approval showed minutes instead of a familiar duration

- **Severity:** Low
- **Category:** Content
- **Fix status:** Verified
- **Commit:** `d939df0`
- **Files:** `client/src/lib/agent-confirmation.ts`, `client/src/hooks/use-webmcp.ts`, `tests/agent-confirmation.test.ts`

**Before:** The approval text said “1080-minute fast.”

**Fix:** Common durations now use a familiar unit. The final live dialog says, “Requested target: 18-hour.” Unit tests cover 90 minutes, 18 hours, and 7 days.
